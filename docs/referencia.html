Proyecto local y base de datos

Cada proyecto utiliza una base de datos local SQLite como fuente de verdad. Los archivos originales permanecen fuera de las tablas binarias: la base conserva identidades, rutas registradas, hashes, relaciones, revisiones y metadatos. Los índices de búsqueda, derivados de imagen y otros artefactos reconstruibles no sustituyen esa base.

Identidad digital

La identidad de un archivo digital no depende de su nombre visible ni del orden en una carpeta. El contenido se identifica mediante SHA-256 y se registran las copias de archivo que materializan ese objeto en rutas concretas. El catálogo describe unidades documentales; un archivo digital se vincula con una unidad mediante una relación registrada.

Originales, derivados y texto editable

La preparación de imágenes produce derivados vinculados con la fuente. Una corrida de extracción produce texto y estructura con su perfil y procedencia. Elegir una extracción para revisar es una decisión explícita. Las correcciones posteriores se registran como revisiones de la capa editable.

Revisiones y auditoría

Las modificaciones importantes se modelan como nuevas revisiones o eventos registrados. Esto permite consultar estados anteriores, deshacer o rehacer cambios donde la interfaz lo ofrece y reconstruir quién realizó una operación. Las operaciones de intercambio y recuperación agregan además simulaciones, confirmaciones y copias de seguridad cuando el riesgo lo requiere.

Catálogo, entidades y relaciones

El catálogo mantiene unidades archivísticas y sus relaciones de ubicación. Los roles de productor y responsable de gestión vinculan personas u organizaciones con unidades concretas. Las entidades canónicas se reutilizan en menciones documentales y relaciones analíticas. El grafo es una vista derivada de esas capas; no crea una base paralela.

Búsquedas

La búsqueda textual utiliza un índice reconstruible de los textos elegidos. La búsqueda semántica utiliza un perfil que define contenido, estados de revisión, modelo que produce las representaciones numéricas del texto (embeddings) y nivel de agregación. Cambiar el índice no modifica el texto ni las entidades del proyecto.

Audio y video

El registro audiovisual extiende la identidad del archivo digital con metadatos temporales. Las corridas de transcripción y sus segmentos se versionan. Las marcas temporales de hablante o anotación tienen intervalos propios y permanecen separadas de la corrida para poder sobrevivir a una nueva transcripción.

Exportaciones

Una configuración de exportación define qué contenido participa y cómo se materializa. Las corridas de exportación registran formato, ruta, tamaño, huellas y una instantánea de la configuración. Exportar texto e imágenes (ZIP) incorpora un manifiesto con la procedencia de los registros, páginas y recortes incluidos.

Intercambio entre copias

El intercambio evita una SQLite compartida en vivo. Los paquetes incrementales contienen eventos posteriores a un punto común. Antes de aplicar un paquete recibido se ejecuta una simulación y se resuelven diferencias cuando corresponde. Las copias completas sirven para iniciar otra copia local; una adopción automática sólo se permite sobre un proyecto vacío después de verificar el paquete y crear una copia de seguridad.

Base de datos y migraciones

La revisión de base congelada para la versión estable 1.0 es 0047_authority_relation_profiles. Las migraciones se ejecutan únicamente mediante archive-workbench db-upgrade y requieren una copia de seguridad previa. Una actualización de código que no cambia el esquema no justifica ejecutar una migración.

Los contratos públicos exportados por archive_workbench.contracts también quedaron congelados para 1.0. El repositorio incluye un verificador de sus schemas y de la revisión SQLite para detectar cambios accidentales antes de publicar una versión.

Extensiones opcionales

La búsqueda semántica, la incorporación desde plataformas y algunos motores de OCR o transcripción son opcionales. La aplicación no exige una nube, una GPU ni un motor único para conservar el modelo del proyecto.

Límites de interpretación

OCR, transcripción, detección de posibles referencias, controles de calidad y similitud semántica producen resultados que necesitan interpretación. Un valor de confianza o similitud describe la salida de un procedimiento concreto; no se publica como una conclusión archivística o analítica sin la revisión correspondiente.
